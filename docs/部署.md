# 部署 AI Navigator

Netlify 连接仓库的 `master` 分支，使用根目录 `netlify.toml`：Node.js 24、构建命令 `npm run build`、发布目录 `.next`。显式启用 `@netlify/plugin-nextjs`，由它生成服务端函数、静态资源和路由，不配置静态 HTML 导出。适配器作为开发依赖纳入锁文件，升级时需检查真实部署。

只有 `next build` 成功不代表站点可访问。发布日志还应出现 Next.js Runtime 的适配与打包步骤；若将 `.next` 原样当作静态目录上传，首页可能返回 Netlify 404。部署完成后用浏览器检查首页、`/community/`、`/practice/` 及 `/guide/` 跳转。配置方式参见 [官方适配器说明](https://github.com/opennextjs/opennextjs-netlify#manually-installing-the-nextjs-runtime)。

```sh
npm ci
npm test
npm run build
```

原版本的混淆安装脚本 `preinstall.js` 及安装入口已删除，不应恢复。无需安装脚本即可运行网站。

社群默认显示历史讨论；发帖、点赞和回复保存在当前浏览器。来源内容保留原文链接。配置 Supabase 后可切换“当前讨论”，此处才读写线上数据库，历史记录不会导入数据库。

## 可选服务配置

- `NEXT_PUBLIC_SUPABASE_URL`、`NEXT_PUBLIC_SUPABASE_ANON_KEY`：Supabase 项目地址与公开匿名密钥。未配置时仍可构建并访问工具目录、实践与历史讨论。
- `OPENAI_API_KEY` 或 `DASHSCOPE_API_KEY`：按所用服务配置 AI 对话接口；密钥只放服务端环境变量。
- `OPENAI_MODEL`：可选模型设置。

不要把服务端密钥放进 `NEXT_PUBLIC_` 变量，也不要提交 `.env.local`。正常公开读取、发帖与举报不需要 service role key。

新数据库先审阅并执行 `COMPLETE_DB_SETUP.sql`，再依序应用 `supabase/migrations/20261031_community.sql` 和 `20261105_reports.sql`。旧数据库先备份、核对既有表和权限；不要直接覆盖。网站发布不会自动执行数据库迁移。

启用线上登录前，在 Supabase Auth 中设置正式站点地址、`/auth/callback` 回调地址及邮件服务。用两个测试账号分别验证登录、发帖、回复、点赞、本人删除和越权拒绝。自动化数据库检查使用本地数据库，不代表云端邮件与多人联调已经完成。
